## 2026-11-07 (v2: three phases)
- New product flow (`evidex/studio.py`, `evidex/agents/studio.py`): Your request → Building → Your draft. Users type a request and/or attach PDF papers or PPTX decks, pick a persona (students, residents/CME, nurses/educators, patients/public) and a format (slides, handout, flowchart, one-page PDF), confirm what Evidex understood, then review a preview, edit or remove statements, approve and download.
- Literature layer (`evidex/sources.py`, migration 006 `source_doc`): PubMed E-utilities (records only from the API), uploaded files as passages; claims cite `pmid:`/`up:` IDs next to spine IDs. Literature numbers must appear in the cited source's text (code). PII check on uploads and requests.
- New exports: flowchart PPTX drawn by code and one-page A4 PDF (fpdf2, DejaVu Sans), both fidelity-checked; patient persona always carries "General information, not advice for any individual. Talk to your doctor."
- UI: Create / My drafts / Library (Encyclopedia, Graph, Review) / How it works. Claim-level review kept under "Detailed review".
- Rules: `docs/PRODUCT_RULES.md`; `docs/SCOPE.md` amended (rules 9-11, approved by the doctor).
- Tests: `tests/test_studio.py` (22). Literature layer not yet covered by `scripts/eval.py`.
- "Not found" now offers 3 clickable in-scope alternatives closest to the request (`studio.SUGGESTIONS`, ranked by shared words; a test checks every suggestion passes the topic rules). "often"/"frequently" no longer read as topic words. Found by the doctor ("Diabetes homecare handout").
- Groq free-tier rate limits: the client now waits them out (up to ~3 minutes in all, honouring retry-after) instead of failing the draft after ~20 s; clearer message if it still fails. Found by the doctor on the live app.
- Daily cap: Groq free tier caps each model at 200k tokens/day. On that cap the client now switches at once to backup models (gpt-oss-120b, then gpt-oss-20b) instead of waiting; plain message if all are capped. Fewer tokens per draft: support judge lists each source once; shorter passages. Tested live: a draft built entirely on gpt-oss-120b, 10/10 statements passed.
- Loading screens: step-by-step status while Evidex reads the request; building screen with progress bar, time left, current step explained, live outline with section ticks, papers found and rotating tips; spinners for re-checking an edit, approving and preparing files; prepared files cached per draft.
- Reading screen: after Continue the form is replaced at once by a "Reading your request" screen (request, persona, format, live checklist and progress bar); the model call runs in the background. Back on the form after a refusal or "can't make this", the request, persona and format are kept.
- Speed: the model client is no longer cached (a cached client kept running old code after an update, so the daily-cap switch never happened live); the Scope Guard no longer treats the "2" in "type 2" as a patient's number (it forced a second call on every type 2 request); guideline words (guidelines, recommendations, ADA, evidence, latest…) are not topic words.
- Headings: "Step 2:"/"Slide 3 -" numbering from the model is stripped (the app numbers steps itself). README rewritten for the three-phase version (live link, demo video, free-tier note); ACCESS.md has contacts, the demo video and the free-tier note.
